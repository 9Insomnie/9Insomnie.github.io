Offensive Security Workspace - AI 辅助渗透测试工作空间

项目概述

Offensive Security Workspace 是一个专为授权安全测试设计的 AI 辅助渗透测试工作空间。它将结构化的工作流程、丰富的漏洞检测技能库、可复用的知识库以及标准化的报告模板整合在一起，为安全研究人员提供一个高效、规范的测试环境。

核心理念

  • 授权优先：所有测试必须在明确的授权范围内进行
  • 证据驱动：每个漏洞发现都需要可复现的证明
  • 知识复用：跨目标的经验和攻击模式可以积累和复用
  • 规范输出：标准化的漏洞报告格式确保专业交付

项目结构

├── .gitignore           # 排除敏感信息和证据

│   ├── parallel_recon.md    # 并行侦察流程

│   └── collect_evidence.md  # 证据收集流程

│   ├── patterns/        # 已验证的漏洞模式和 PoC

核心功能

1. 结构化工作流程

项目提供四个核心工作流程，确保测试过程的系统性和完整性：

新目标初始化 (workflows/new_target.md)

  • 建立目标工作目录结构
  • 确认授权范围（Rules of Engagement）
  • 配置测试环境

并行侦察 (workflows/parallel_recon.md)

  • 多维度并行信息收集
  • 技术栈识别
  • 攻击面映射

漏洞检测调度 (workflows/hunt_dispatch.md)

  • 根据侦察结果选择合适的检测技能
  • 按优先级排序攻击路径
  • 执行针对性漏洞检测

证据收集 (workflows/collect_evidence.md)

  • 规范化证据存储
  • 保持原始时间戳和文件名
  • 生成可复现的漏洞证明

2. 丰富的漏洞检测技能库

HUNT_INDEX.md 定义了超过 50 种漏洞检测技能，涵盖：

类别示例技能
Web 应用漏洞SQL 注入、XSS、CSRF、SSRF、文件上传
认证与授权认证绕过、会话管理、MFA 绕过
云与基础设施AWS 配置错误、Kubernetes 安全、CI/CD 安全
平台框架Spring Boot、Laravel、Next.js、ASP.NET
Web3智能合约审计、Meme 币审计
侦察与 OSINT子域名发现、TLS 分析、开源情报

每个技能都是模块化的，可以根据目标技术栈灵活加载。

3. 跨目标知识库

kb/ 目录提供可复用的安全知识：

  • 技术栈知识 (kb/stacks/): 针对特定技术的安全测试要点
  • 漏洞模式 (kb/patterns/): 已验证的漏洞利用模式和 PoC
  • 目标档案 (kb/targets/): 完成的目标分析报告

经验法则：如果某个漏洞在两个相同技术栈的目标上被确认，那么它很可能也存在于第三个目标上，除非有明确证据表明不存在。

4. 标准化输出格式

每个漏洞发现都必须包含：

字段描述
Summary一段话概述
Impact攻击者能获得什么
Root Cause为什么存在这个漏洞
Trigger Conditions触发漏洞的条件
Proof of Concept分步复现步骤
Payload提供可用的 payload
Detection防御者如何检测
Remediation最小化代码修复
References相关 CVE/CWE/OWASP

使用场景

授权渗透测试

为客户提供专业的渗透测试服务，从侦察到报告生成的完整流程。

安全研究

研究新型漏洞利用技术，积累可复用的攻击模式和 PoC。

Bug Bounty

参与众测平台的安全测试，高效定位和报告漏洞。

红队演练

企业内部红队活动，模拟真实攻击场景。

安全实践

证据处理

  • 原始证据存储在 evidence/<target-id>/ 或 targets/<id>/exploits/
  • 永远不要提交密钥、凭证或敏感信息
  • 保持原始时间戳和文件名
  • 分享前脱敏第三方 PII
  • 每个 Verified 或 Likely 发现必须引用证据文件

通信原则

  • 简洁明了
  • 明确陈述假设
  • 标记不确定的结论
  • 区分验证级别：Verified / Likely / Possible / Speculative

禁止行为

  • 永远不要伪造漏洞
  • 没有证据时永远不要声称成功利用
  • 永远不要省略假设
  • 永远不要隐藏不确定性
  • 永远要解释推理过程

技术实现

  • 代码生成使用 Python 3.11+
  • 使用类型注解
  • 添加日志记录
  • 支持命令行参数
  • 失败时提供有意义的错误信息
  • 脚本尽可能幂等

快速开始

  1. 新任务：按照 workflows/new_target.md 创建 targets/<id>/
  2. 侦察：按照 workflows/parallel_recon.md 执行
  3. 检测：通过 workflows/hunt_dispatch.md 和 HUNT_INDEX.md 调度
  4. 证据：按照 workflows/collect_evidence.md 收集

总结

Offensive Security Workspace 通过结构化的工作流程、丰富的技能库、可复用的知识库和标准化的输出格式，为安全研究人员提供了一个高效、规范的渗透测试环境。它强调授权测试、证据驱动和知识积累，帮助安全团队提升测试效率和专业度。
